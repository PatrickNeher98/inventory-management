Factory Inventory Management System

Architecture overview: Vue 3 frontend, FastAPI backend, in-memory JSON data

1. Overview

A full-stack demo application for viewing factory inventory, orders, demand forecasts, backlog and spending. The Vue 3 single-page app (port 3000) calls a Python FastAPI service (port 8001) over HTTP. There is no database: at import time server/mock_data.py reads JSON files from server/data/ into Python lists and dicts, and every request filters those structures in memory.

Four global filters (Time Period, Warehouse, Category, Order Status) are shared across views and sent to the API as query parameters.

4. Data flow: a filter change

  1. The user changes a select in FilterBar.vue (period, warehouse, category, status). Each select is bound with v-model to a ref from useFilters().
  2. Those refs (selectedPeriod, selectedLocation, selectedCategory, selectedStatus) are module-level singletons, so every view sees the same state.
  3. The active view has a watch on the refs it uses and calls its loadData(). Dashboard and Orders watch all four; Inventory, Demand and Backlog watch warehouse and category; Spending watches period only.
  4. loadData() calls getCurrentFilters(), which returns {warehouse, category, status} and maps the period to month when it is not all.
  5. The api.js method builds a query string, skipping any value equal to all, and issues the axios GET (the Dashboard runs several in parallel with Promise.all).
  6. The FastAPI route receives the optional query params, calls apply_filters() (warehouse, category, status; case-insensitive for category and status) and filter_by_month() (month YYYY-MM or quarter Q1-2025 to Q4-2025, matched against order_date) over the in-memory lists.
  7. FastAPI validates the result against the Pydantic response_model and returns JSON.
  8. The view stores the raw response in refs (e.g. allOrders, inventoryItems); computed properties derive chart series, KPIs and tables, and the template re-renders.
Inventory has no time dimension, so the month filter is not applied to inventory. Currency display (USD or JPY at a fixed rate of 150) is applied client-side by utils/currency.js from the current locale; the API always returns USD values.

Client/server mismatch. api.js defines calls to /api/tasks (GET, POST, DELETE, PATCH) and /api/purchase-orders (POST, and GET by backlog item), but no matching routes exist in server/main.py. The server loads purchase_orders.json and uses it only to compute has_purchase_order. The CreatePurchaseOrderRequest model is defined but unused by any route. Those client features (Tasks modal, purchase order creation) will receive 404 responses against the current backend.

The server also allows all CORS origins (allow_origins=["*"]) and binds to 0.0.0.0, which is appropriate for a local demo only.

7. Testing and tooling

  • Backend tests: tests/backend (test_dashboard.py, test_inventory.py, test_misc_endpoints.py) using pytest with FastAPI TestClient via a client fixture in conftest.py. Config in tests/pytest.ini. About 40 test functions.
  • Frontend tests: none configured; client/package.json has only dev, build and preview scripts. Browser checks use Playwright MCP tools against ports 3000 and 8001.
  • Data generation: server/generate_data.py and scripts/ exist alongside the JSON data files.
  • Claude Code tooling (.claude/): agents (vue-expert, code-reviewer, security-auditor), commands (start, stop, test, demo-branch, reset-branch, optimize), the backend-api-test skill, hooks and MCP config.
  • Repository hygiene: the repository is public. client/.npmrc pins the public npm registry and client/package-lock.json is gitignored.
  • Run locally: cd server && uv run python main.py and cd client && npm install && npm run dev. API docs are served by FastAPI at /docs.
